六、幂等与重复请求
DEMO 服务端以 idempotencyKey 保存已执行响应。同一个发炮 idempotencyKey 重复提交时返回同一个 bulletId 与同一余额，不重复扣款。同一命中 idempotencyKey 重复提交不重复派奖。

七、响应丢失恢复
发炮或命中请求若客户端未收到响应，会用 transactionId 调用 settle()/GET /api/settlement 查询服务端是否已经处理：
- found=true：采用服务端原响应恢复界面。
- found=false：不得在前端假造资金结果；平台可按同一 idempotencyKey 安全重试。

八、PRODUCTION 映射示例
在游戏脚本加载前注入：

window.YY9_GAME_MODE = 'PRODUCTION';
window.YY9_PLATFORM_CONFIG = {
  apiBase: 'https://你的正式API域名',
  authToken: '由平台会话动态注入，不可写死',
  sessionId: '平台会话ID',
  deviceId: '平台设备ID',
  returnUrl: '/game-halls/fishing-hall.html',
  endpoints: {
    initializeGame: { method:'POST', url:'/game/init' },
    getProfile: { method:'GET', url:'/player/profile' },
    getBalance: { method:'GET', url:'/wallet/balance' },
    refreshBalance: { method:'GET', url:'/wallet/balance' },
    getGameConfig: { method:'GET', url:'/games/deep-sea/config' },
    getGameState: { method:'GET', url:'/games/deep-sea/state' },
    restoreGameState: { method:'GET', url:'/games/deep-sea/state' },
    saveGameState: { method:'POST', url:'/games/deep-sea/state' },
    fire: { method:'POST', url:'/games/deep-sea/fire' },
    placeBet: { method:'POST', url:'/games/deep-sea/fire' },
    hitFish: { method:'POST', url:'/games/deep-sea/hit' },
    fishResult: { method:'POST', url:'/games/deep-sea/hit' },
    getResult: { method:'POST', url:'/games/deep-sea/hit' },
    settle: { method:'GET', url:'/wallet/transaction' },
    getHistory: { method:'GET', url:'/games/deep-sea/history' },
    getRebate: { method:'GET', url:'/rebate/pending' },
    claimRebate: { method:'POST', url:'/rebate/claim' },
    bossEvent: { method:'POST', url:'/games/deep-sea/boss-event' }

  },
  realtimeType: 'ws',
  realtimeUrl: 'wss://你的正式实时服务'
};

九、正式环境硬性要求
- PRODUCTION 不允许接口失败后切到 DEMO。
- 正式余额、扣款、捕获、返奖、返水、历史、RTP/命中率由平台后端权威控制。
- authToken 不得打包进静态游戏文件。
- 服务器必须自行验证 cannonValue、bulletId、fishType、sessionId、roundId、幂等键和交易状态。
